Why isn't YIELDDISC working in LibreOffice?

YIELDDISC exists in LibreOffice 25.8.7.3, but it is not a drop-in match for Excel — our executed tests found real behavioral differences (detailed in the test results on this page). If a formula that works in Excel or Google Sheets misbehaves in LibreOffice, compare your usage against the failing cases above before assuming your data is wrong.

Google Sheets: 1 case inconclusive. Our corpus is an Excel-authored .xlsx, and Google’s importer does not map every OOXML storage prefix (_xlfn., _xlfn._xlws., _xlpm.) — nor does the .xlsx export preserve full float precision or a blank result. Where the disagreement is explained by that round trip we report it as inconclusive rather than as a Sheets behavior. Google documents this function, so the result is not evidence of missing support. See the methodology page for the full caveat and the planned re-run with plain function names.

Discovered quirks

  • =YIELDDISC(A3,A2,A4,A5,A6) on LibreOffice Calc returned #VALUE!, but the documented/expected result is #NUM!. The Remarks publish: "If settlement >= maturity, YIELDDISC returns the #NUM! error value."; MISMATCH vs expected: expected '#NUM!', got '#VALUE!'
  • =YIELDDISC(A2,A3,0,A5,A6) on LibreOffice Calc returned #VALUE!, but the documented/expected result is #NUM!. The Remarks publish: "If pr <= 0 or if redemption <= 0, YIELDDISC returns the #NUM! error value."; MISMATCH vs expected: expected '#NUM!', got '#VALUE!'
