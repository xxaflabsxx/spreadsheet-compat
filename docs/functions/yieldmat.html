Why isn't YIELDMAT working in LibreOffice?

YIELDMAT exists in LibreOffice 25.8.7.3, but it is not a drop-in match for Excel — our executed tests found real behavioral differences (detailed in the test results on this page). If a formula that works in Excel or Google Sheets misbehaves in LibreOffice, compare your usage against the failing cases above before assuming your data is wrong.

Discovered quirks

  • =YIELDMAT(A3,A2,A4,A5,A6,A7) on LibreOffice Calc returned #VALUE!, but the documented/expected result is #NUM!. The Remarks publish: "If settlement >= maturity, YIELDMAT returns the #NUM! error value."; MISMATCH vs expected: expected '#NUM!', got '#VALUE!'
  • =YIELDMAT(A2,A3,A4,-0.01,A6,A7) on LibreOffice Calc returned #VALUE!, but the documented/expected result is #NUM!. The Remarks publish: "If rate < 0 or if pr <= 0, YIELDMAT returns the #NUM! error value."; MISMATCH vs expected: expected '#NUM!', got '#VALUE!'
  • =YIELDMAT(A2,A3,A4,A5,0,A7) on LibreOffice Calc returned #VALUE!, but the documented/expected result is #NUM!. The second half of the same Remark: pr <= 0 is a #NUM!.; MISMATCH vs expected: expected '#NUM!', got '#VALUE!'

Where YIELDMAT behaves differently

  • Bond and treasury functions after a migration: what actually breaks
    Executed across 26 fixed-income functions and 161 cases: ODDFPRICE and ODDFYIELD are literal stubs in LibreOffice, TBILLPRICE prices a two-year bill, INTRATE's default basis loses a day, and MDURATION is wrong on actual/actual. 83 of 84 documented #NUM! cases arrive as #VALUE!. Google Sheets matched 127 of 161.
  • Every error code LibreOffice reports as #VALUE!
    Across our 2,334-case executed corpus, 272 cases in 135 functions return #VALUE! in LibreOffice Calc 25.8.7.3 where Microsoft documents #NUM! (244), #N/A (15), #DIV/0! (10) or #REF! (3). Google Sheets returns the documented code on 239 of the 249 it has a function for. Identical in all four LibreOffice builds tested.
